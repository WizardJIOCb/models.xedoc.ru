# Model Studio — генерация на локальном ПК

Отдельный режим [models.xedoc.ru/generate-model](https://models.xedoc.ru/generate-model): изображение → модель GLB → скелет человека → движение SMPL-X RP v1 → WebGL playground с ragdoll. Обычный режим создания анимаций остаётся на главной странице сайта.

## Подготовка после клонирования

В репозитории находятся интерфейс Studio, локальный API, workflow Pixal3D, скрипты подготовки скелета и переноса движения. Нейросетевые веса, установленная ComfyUI, исполняемый комплект Kimodo и Blender устанавливаются отдельно. `start.bat` рассчитан на уже подготовленный Windows-компьютер: он запускает сервисы, но не устанавливает весь набор зависимостей.

Перед первым запуском нужны:

- Node.js с npm, совместимые с версией Vite из `apps/studio-web/package-lock.json`.
- Рабочая ComfyUI с узлами workflow `config/pixal3d-api.json`, совместимым GPU-окружением и всеми перечисленными в workflow весами Pixal3D/TRELLIS.2, DINO, MoGe и BiRefNet. API должен отвечать на `127.0.0.1:8188`.
- Среда Python для Studio с пакетами `aiohttp` и `Pillow`; для численных тестов нужен также `numpy`. Текущий запускатор использует Python из среды ComfyUI.
- Исполняемый комплект Kimodo: `bin/kimodo-demo.exe`, `bin/kmd-generate.exe` и его runtime-зависимости. Нужны веса `models/kimodo-smplx-rp-v1-f32.gguf` и каталог `generated/llm2vec-text-bundle` с `embedding.gguf`, `final-norm.gguf`, `tokenizer.gguf` и 32 файлами `layer-00.gguf` … `layer-31.gguf`. Kimodo слушает `127.0.0.1:8094`; запускатор выбирает Vulkan и обрабатывает текстовый кодировщик блоками по четыре слоя.
- Blender; в текущей локальной установке используется Blender 5.1.
- Отдельная среда MediaPipe Pose и модель `pose_landmarker_heavy.task`. Скрипт ниже подготавливает только этот компонент; ему нужен установленный `uv`.
- Для публичного доступа — Windows OpenSSH, настроенный SSH-профиль `myserver`, обратные туннели и Nginx на сервере. Для работы только через локальный адрес новый туннель Studio не требуется.

Соберите интерфейс из корня репозитория:

```powershell
Set-Location apps\studio-web
npm ci
npm run build
Set-Location ..\..
```

Результат появляется в `apps/studio-web/dist/`; он исключён из Git и нужен API для раздачи страницы. После изменения исходников повторите `npm run build` в `apps/studio-web`.

Установка компонента распознавания позы из корня репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install-Pose.ps1
```

Скрипт создаёт Python 3.12-окружение, устанавливает зафиксированные версии MediaPipe/Pillow, скачивает Pose Landmarker Heavy и проверяет SHA256. Это не установка ComfyUI, Kimodo или их весов.

### Локальные данные и необязательное демо

Исходные картинки, модели, сессионная история и движения лежат в `data/`; журналы — в `.runtime/`, отчёты ручных проверок — в `work/`. Эти каталоги, `node_modules/` и сборка `dist/` исключены из Git. Клонирование репозитория не переносит существующую библиотеку, общие ссылки или подготовленные веса.

Кнопка «Попробовать Doom Slayer» использует необязательный локальный файл `data/demo/doom-rigged.glb`. Этот ранее созданный персонаж в репозиторий не включён. Без файла демо недоступно; генерация и просмотр собственных моделей работают независимо от него.

## Запуск после перезагрузки

Откройте **`start.bat` из корня репозитория**. Запускатор поднимает ComfyUI, Kimodo, локальный API и SSH-туннель, затем открывает страницу генерации. Уже работающие сервисы используются повторно. Компьютер должен быть включён, а каталоги с моделями доступны.

Для запуска только на компьютере, без открытия браузера и нового публичного туннеля:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Studio.ps1 -LocalOnly -NoBrowser
```

Параметры можно передать напрямую: `start.bat -LocalOnly -NoBrowser`. При запуске проверяются зависимости и ответы сервисов; для публичной страницы отдельно проверяется HTTPS. Если туннель ещё недоступен, появится сообщение с расположением журнала и откроется локальная страница. Туннель продолжит попытки соединения.

Локальная страница: [127.0.0.1:8095/generate-model](http://127.0.0.1:8095/generate-model). Наличие `start.bat` само по себе не добавляет программу в автозагрузку Windows.

## Как пользоваться

1. Загрузите PNG, JPEG или WebP размером до 20 МБ. Выберите объект или человека и качество модели.
2. Дождитесь генерации. Объект можно вращать и скачать как GLB.
3. Для человека после создания сетки выполняется примерная автоматическая расстановка 17 костей и весов. При успешном результате доступны анимация и ragdoll.
4. Опишите движение, желательно по-английски, например `A person walks forward, waves with their right hand, then stops.` После расчёта клип можно проиграть на модели и скачать вместе с ней в GLB.
5. В playground переключайте клипы, применяйте удар и возвращайте персонажа к анимации. Физика ragdoll рассчитывается в браузере.

Без регистрации история привязана к cookie текущего браузера. При регистрации или входе не привязанные к аккаунту генерации этого браузера переходят в библиотеку вошедшего пользователя. После входа с другого устройства доступна та же библиотека. Выход из аккаунта закрывает доступ к его приватным файлам. Сами файлы остаются на компьютере в `data/jobs/`.

### Галерея, профили и комментарии

Перед «Твоей библиотекой» на странице генерации показывается галерея сообщества. Полная галерея доступна на `/gallery`, поиск авторов — на `/profiles`. Можно искать модели по названию и описанию, открывать страницу модели `/model/{id}`, переходить к автору `/profile/{username}` и запускать модель в публичном playground.

Новая модель по умолчанию публичная: галочка «Публиковать в галерее» включена перед генерацией. Для приватного результата её нужно снять. У готовой своей модели можно изменить название, описание и видимость. Приватные результаты исчезают из галереи, публичного профиля и поиска; явное переключение в приватный режим также отключает ранее выданную общую ссылку. Старые генерации без настройки видимости остаются приватными, пока владелец сам не опубликует их.

Карточки используют снимок самой 3D-модели, который сохраняется при её открытии владельцем. До появления снимка показывается заглушка. Исходный референс не используется как публичная обложка и остаётся доступен только владельцу.

Регистрация использует уникальный ник из 3–24 латинских букв, цифр и подчёркивания, отображаемое имя и пароль. На странице `/profile` можно изменить имя и описание профиля. Электронная почта и внешние сервисы входа не требуются. Комментарии к публичным моделям могут оставлять вошедшие пользователи; автор комментария и владелец модели могут его удалить. Смена видимости модели закрывает и публичный доступ к её обсуждению.

Аккаунты, хеши паролей, хеши сессий и комментарии хранятся локально в `data/community.sqlite3`; файл исключён из Git вместе с остальными данными. При переносе установки сохраняйте не только `data/jobs/`, но и базу сообщества. Публичная галерея и профили, как и генерация, требуют доступного локального Studio и туннеля.

В публичном playground (`/playground?model=…`) та же лента комментариев доступна сразу под 3D-плеером. Кнопка «Комментарии к модели» прокручивает страницу к обсуждению. Читать можно без входа, писать — после входа в профиль.

### Удаление лишних частей

Владелец открывает модель в playground → «Очистка модели» → «Редактировать части». Режим «Отдельная часть» выделяет связанный фрагмент одним кликом. Для верёвок, соединённых с телом, используется кисть: она выделяет видимую поверхность, не затрагивая поверхность за ней. Правой кнопкой мыши можно вращать камеру, Shift снимает выделение. На телефоне для вращения переключитесь на «Отдельная часть». «Найти мелкие фрагменты» выделяет детали меньше выбранного количества треугольников; перед удалением проверьте подсветку со всех сторон.

Удаление сначала меняет только предпросмотр. Доступны отмена шага, снятие выделения и выход без сохранения. «Сохранить модель» создаёт отдельную версию GLB; исходная `model.glb` остаётся на диске. «Вернуть исходную модель» восстанавливает оригинал. Изменения попадают в скачивание, галерею и общие ссылки; редактировать их может только владелец. Сохранённые положение, поворот и окружение сохраняются. При одновременном редактировании в двух вкладках устаревшая версия не перезапишет новую.

После сохранения очистки прежний скелет и движения перестают быть активными: создайте скелет заново, используя сохранённые ручные опорные точки при необходимости. Возврат оригинала возвращает его исходный скелет и движения. Текстуры, UV и материалы сохраняются. Кисть удаляет треугольники, но не зашивает отверстия; это очистка сетки, а не инструмент скульптинга или уменьшения размера файла.

API: `POST /api/model-studio/jobs/{id}/mesh-edit` с `{expectedRevision, remove: [{mesh, primitive, faces}]}`; `POST /api/model-studio/jobs/{id}/mesh-restore` с `{expectedRevision}`. Индексы треугольников относятся к текущей сохранённой версии. Во время генерации, построения скелета или движения сохранение очистки недоступно. Версии хранятся в `meshes/{uuid}/model.glb`, активная версия задаётся в метаданных задания. Поддерживается исходная статическая GLB без сжатия геометрии; режим редактирует источник, даже когда у персонажа уже есть скелет.

### Подготовка скелета

В ручном режиме зеркально перепутанные левая и правая стороны исправляются при подтверждении проверки точек и перед созданием скелета. Если и плечи, и таз размечены наоборот, редактор меняет названия всех пар целиком, сохраняя координаты и глубину. Исправление видно в редакторе, сохраняется в черновике и отменяется кнопкой «Отменить». Если плечи и таз противоречат друг другу, нужно уточнить разметку; отдельные точки автоматически не перемещаются.

Готовую модель можно подготовить к анимации без повторной генерации геометрии: откройте «Подготовить персонажа», выберите «Вид спереди», выставьте углы X/Y/Z и нажмите «Создать скелет». Углы вращают исходную модель; перетаскивание мышью вращает камеру. У готового персонажа кнопка «Настроить заново» открывает тот же режим.

Сохраняется новая версия скелета; прежние успешные версии и движения не перезаписываются. Во время подготовки можно закрыть страницу, очередь восстановится после запуска Studio. Отдельная подготовка скелета использует CPU и может выполняться параллельно с GPU-генерацией другой модели.

Для вертикальной A-позы используется геометрическая подгонка. Для согнутых и поднятых рук применяется локальный MediaPipe Pose Landmarker Heavy: Blender отрисовывает модель с семи ракурсов. Каждый сустав восстанавливается по согласованному большинству наблюдений: минимум три ракурса, угловое разделение от 25°, ошибка проекции до 8 см для модели высотой 2 м. Ошибочные наблюдения отбрасываются отдельно для каждого сустава; затем проверяются близость к сетке и пропорции конечностей. Создаются 17 костей и веса через Blender bone heat. При неполной привязке применяется геометрический резервный способ. Распознавание работает на CPU, изображения не отправляются во внешние сервисы.

Нужен один человек в полный рост, стоящий вертикально, лицом вперёд. Предметы, животные, закрытые конечности и сложные позы могут не пройти проверку; исходная статическая GLB и прежний успешный скелет при этом остаются доступными. Весам брони, плеч и одежды на сильных изгибах может понадобиться ручная доводка. Пальцы и мимика не анимируются. Плащ остаётся частью общей сетки без отдельной симуляции ткани. Возврат из ragdoll сбрасывает персонажа к клипу, отдельной анимации подъёма нет.

### Ручная расстановка опорных точек

Если автоматическое распознавание не справляется с бронёй, шлемом или согнутыми руками, в playground откройте «Подготовить персонажа» → «Вручную». Сначала выровняйте исходную модель в автоматическом режиме: при ручной разметке её поворот фиксируется.

1. Выберите точку в списке и нажмите на соответствующее место модели. После новой точки редактор переходит к следующей. Лево и право считаются со стороны персонажа: его левая рука справа на фронтальном виде.
2. Отметьте 18 точек: голову, основание шеи и по восемь точек на каждой стороне тела — плечо, локоть, запястье, кисть, бедро, колено, щиколотку и носок стопы.
3. Переключайте виды «Спереди», «Слева», «Справа», «Сзади» и перетаскивайте маркеры, чтобы суставы находились внутри нужных частей тела. При клике учитывается толщина ближайшей части сетки; броня и соприкасающиеся конечности всё равно требуют проверки глубины. «Точное положение точки» позволяет ввести координаты; Z задаёт глубину. Координаты относятся к модели ростом 2 м, без сдвига по сцене.
4. Подтвердите проверку спереди и сбоку и нажмите «Создать скелет по точкам». Получатся те же 17 костей, движения и ragdoll, без запуска распознавателя позы.

Черновик, включая незавершённую разметку, сохраняется автоматически и восстанавливается после перезагрузки. Доступны отмена, удаление выбранной точки и начало заново. После изменения углов в автоматическом режиме старую разметку можно использовать, вернув её исходный поворот, либо разметить модель заново. Успешные версии скелета и прежние движения сохраняются отдельно. Черновик доступен только владельцу.

Ручные точки определяют расположение костей; веса сетки по-прежнему рассчитываются автоматически. Это не редактор весов: в местах контакта рук с поясом, под бронёй и на одежде могут оставаться нежелательные деформации.

### Фон и земля модели

Ссылка `/playground?model=...` открывает публичный просмотр. Если текущая сессия принадлежит владельцу, сверху появляется кнопка «Настроить мою модель», которая открывает редактор `/playground?job=...`. Такая же кнопка доступна владельцу по общей ссылке `?share=...` и обновляется после входа или выхода из аккаунта.

На странице результата и в playground автору доступна панель «Окружение модели». Готовые фоны: студия, горное утро, закат и звёздная ночь. Панорамные фоны окружают сцену на 360°; их можно поворачивать отдельно от персонажа. Для земли доступны студия, камень, песок и трава, плоскость или круглая площадка, масштаб повторения текстуры и переключатель сетки.

«Свой фон» и «Своя текстура» позволяют загрузить отдельные PNG/JPEG/WebP до 8 МБ и 32 мегапикселей каждый. Для панорамы подходит изображение 2:1; обычную фотографию можно показывать в режиме «Обычная картинка» с заполнением кадра. Сервер пересохраняет изображения в WebP, удаляет метаданные и ограничивает разрешение до 4096 пикселей по каждой стороне.

Правки сразу видны в просмотре. «Сохранить окружение» записывает их в модель и обновляет превью; «Вернуть сохранённое» отменяет черновик. Кнопка «Поделиться моделью» дожидается сохранения окружения вместе с положением и поворотом. Публичная страница и общая ссылка открывают одну и ту же сохранённую сцену. Окружение относится к просмотру на сайте и не встраивается в скачиваемый GLB; круглая площадка меняет внешний вид пола, физический пол остаётся плоским.

API: `PUT /api/model-studio/jobs/{id}/environment`, только для владельца завершённой модели. Multipart-форма содержит `settings` — JSON с `background`, `backgroundProjection`, `backgroundRotation`, `ground`, `groundShape`, `groundScale`, `showGrid`, `expectedRevision` — и необязательные файлы `backgroundImage` и `groundImage`. Конфликт ревизии возвращает 409. Сохранение настроек и обеих текстур выполняется вместе. По публичному адресу и общей ссылке доступны только выбранные текстуры; исходный референс и сохранённые, но не выбранные текстуры остаются приватными.

### Библиотека и исходное изображение

Файлы моделей, скелетов, движений, превью и окружения сохраняются в HTTP-кеше браузера. При повторном открытии браузер проверяет актуальность файла по `ETag`/`Last-Modified`: неизменившийся файл получает ответ `304` без повторной передачи содержимого. Это действует в редакторе, публичном просмотре и по общей ссылке. Политика `private, no-cache` разрешает хранение в браузере, но требует проверки сервера перед повторным использованием; права доступа и отзыв ссылки проверяются при каждом запросе. После изменения файла сервер передаёт новую версию. Исходное изображение и JSON API остаются с `no-store`. Разбор GLB и подготовка сцены WebGL при открытии по-прежнему выполняются в браузере.

Кнопка «Посмотреть референс» у готовой модели открывает исходное изображение крупно, с его размером в пикселях и ссылкой «Открыть оригинал». Она доступна владельцу на странице генерации и в playground. Закрыть просмотр можно крестиком или Escape. По общей ссылке исходная картинка остаётся приватной.

У карточки генерации есть корзина; кнопка «Удалить с ошибками» выбирает завершившиеся с ошибкой задачи. Подтверждение перечисляет записи, которые будут удалены вместе с файлами Studio, скелетами и движениями. Пока для модели выполняется генерация, скелет или движение, удаление запрещено. Отдельные копии и временные файлы ComfyUI эта операция не очищает; на исходном компьютере ComfyUI использует также рабочие каталоги `D:\AI\Comify`.

### Положение, поворот и общие ссылки

Для крупных GLB интерфейс дополнительно использует отдельный кеш файлов в браузере (Cache Storage): до 6 файлов, суммарно до 256 МиБ, не более 128 МиБ на файл, срок хранения до 7 дней с последнего использования. Это помогает, когда обычный HTTP-кеш браузера не удерживает большую модель. Кеш сохраняется после перезагрузки страницы. Перед каждым чтением выполняется запрос с `If-None-Match`: только ответ `304` разрешает использовать сохранённые байты; новая версия скачивается заново. Выход из аккаунта, приватность и отзыв ссылки проверяются сервером, а без связи кеш не открывается. При недоступном хранилище или нехватке места просмотр продолжает работать через обычное скачивание. Исходные изображения не попадают в этот кеш.

Индикатор различает проверку сохранённой модели, скачивание, чтение из кеша и подготовку 3D-сцены. Разбор GLB, декодирование текстур и подготовка редактора по-прежнему выполняются при открытии, даже если файл уже сохранён в браузере.

В playground панель «Положение модели» задаёт X/Y/Z от −5 до +5 метров с шагом 0,01 м. Положение и углы поворота исходной модели сохраняются автоматически вместе; кнопка «Сохранить настройки» позволяет сохранить их сразу. Настройки восстанавливаются при открытии модели и отображаются по общей ссылке. «Поделиться моделью» дожидается сохранения последних правок; при ошибке сохранения ссылка не выдаётся.

Положение применяется также к анимации и ragdoll и сохраняется при восстановлении. Поворот, уже учтённый при создании скелета, повторно к готовому персонажу не применяется. «Поставить на пол» выравнивает нижнюю точку текущей сетки по полу; при длинном плаще или аксессуарах высоту можно уточнить вручную. Это настройки сцены playground: скачиваемый GLB не переписывается.

«Поделиться моделью» создаёт повторно используемую ссылку `/playground?share=...`. Получатель может просматривать и скачивать модель и готовые движения, проверять ragdoll. Исходная картинка, библиотека и редактирование остаются доступны владельцу своей сессии. Ссылка открывается, пока локальный ПК и Studio работают. В том же окне её можно отключить; следующая выдача создаёт новый токен. Удаление модели также отключает доступ.

Основные операции API:

| Метод и маршрут | Назначение |
|---|---|
| `DELETE /api/model-studio/jobs/{id}` | Удалить завершённую задачу владельца |
| `PATCH /api/model-studio/jobs/{id}/placement` | Сохранить положение и необязательный поворот |
| `POST /api/model-studio/jobs/{id}/share` | Создать или получить общую ссылку |
| `DELETE /api/model-studio/jobs/{id}/share` | Отозвать общую ссылку |
| `GET /api/model-studio/shares/{token}` | Прочитать общедоступную модель и настройки |

Пример тела запроса сохранения:

```json
{
  "position": { "x": 0, "y": -0.14, "z": 0 },
  "rotation": { "x": -10, "y": 0, "z": 0 }
}
```

Положение задаётся в метрах, углы — в градусах от −180 до +180. Запрос только с `position` сохраняет прежний поворот. Операции владельца требуют сессионную cookie и проходят проверку происхождения запроса.

### Готовые движения и комментарии в playground

В списке «Движение» первым выбран пункт «Ходьба по кругу»: это прежняя встроенная анимация `Walk` со следованием по арене. Ниже находятся готовые движения SMPL-X RP v1 из истории Kimodo и отдельно движения, созданные для выбранной модели. Список истории обновляется автоматически. Для применения нужен готовый скелет; после очистки геометрии его необходимо подготовить заново.

Первый выбор движения из истории переносит уже рассчитанные суставы и движение корня на скелет персонажа через локальный Blender. Повторная нейросетевая генерация не запускается. GLB сохраняется в `data/jobs/{id}/library/{rigRevision}/{motionId}/animated.glb` и затем используется повторно. Пересоздание скелета меняет ключ кеша. Одновременные запросы одного движения используют один расчёт; до его завершения нельзя удалить модель, очистить её геометрию или пересоздать скелет. Кеш доступен через соответствующий маршрут владельца, публичной модели или действующей общей ссылки с проверкой прав при каждом запросе.

`GET /api/model-studio/motion-library` возвращает готовые совместимые записи истории. Восемь существовавших на момент добавления библиотеки движений включены как общие пресеты; их ID перечислены в `SHARED_PRESETS`. Это открывает только сами движения: исходные модели и картинки сохраняют свои права. Новые движения, связанные с приватными задачами Studio, видит только их владелец. Готовые GLB движений можно скачивать обычной кнопкой в playground; выбранное движение сохраняется в параметре `motion` ссылки.

Комментарии находятся непосредственно под плеером как на странице владельца `?job=...`, так и в публичном просмотре `?model=...`. Для отправки требуется вход в аккаунт. У приватной модели комментарии доступны только владельцу; общая ссылка на приватную модель не открывает её обсуждение. Автоматическое обновление сведений о модели сохраняет ещё не отправленный текст комментария.

Перед использованием ознакомьтесь с условиями весов в [карточке NVIDIA Kimodo-SMPLX-RP-v1](https://huggingface.co/nvidia/Kimodo-SMPLX-RP-v1). Доступ через сайт не меняет условия лицензирования; веса посетителям не раздаются.

### Публичный Nginx

`.deploy/nginx.conf` и `deploy/nginx.conf` содержат актуальные маршруты существующего домена, локальные порты обратных туннелей и пути сертификатов на сервере. При публикации их содержимое сверено с действующей конфигурацией сервера. Локальная резервная копия `deploy/nginx.before.conf` исключена из Git.

`deploy/apply-nginx.sh` — сохранённый скрипт разовой, заранее проверенной миграции. Он проверяет фиксированный SHA256 прежней конфигурации, ожидает подготовленные файлы в `/tmp`, сохраняет резервную копию и запускает `nginx -t` перед перезагрузкой. Это не универсальная команда обновления: на уже изменённом Nginx скрипт намеренно остановится. Для нового развёртывания сначала сверяйте текущие маршруты, сертификаты, туннели и конфигурацию; не подменяйте ожидаемый hash без проверки различий. Обычное обновление интерфейса Studio на существующей установке требует сборки локального frontend, а изменение Python API — контролируемого перезапуска локального процесса.

## Проверки и диагностика

Из корня репозитория можно запустить тесты API и численные проверки распознавания. Они используют управляемые тестовые данные и не запускают нейросетевую генерацию:

```powershell
& 'C:\Projects\comfy\ComfyUI\.venv\Scripts\python.exe' -m unittest discover -s tests -v
```

На другом компьютере замените путь на Python с установленными `aiohttp`, `Pillow` и `numpy`. Актуальный результат и число тестов определяются этим запуском. Проверки покрывают изоляцию истории и файлов, валидацию загрузки, очереди, удаление, общие ссылки, сохранение настроек и геометрию суставов. Тесты сообщества дополнительно проверяют регистрацию, вход и выход, привязку библиотеки к аккаунту, SQLite, приватность, превью, поиск, модерацию комментариев и смену владельца во время запроса.

После `npm ci` в `apps/studio-web` из корня репозитория доступны проверки состояния интерфейса и преобразований модели без браузера и нейросетевой генерации:

```powershell
node tests/test_studio_settings.mjs
node tests/test_viewer_orientation.mjs
node tests/test_viewer_placement.mjs
```

Состояние компонентов: [локальный health API](http://127.0.0.1:8095/api/model-studio/health). Журналы Studio и туннеля лежат в `.runtime/`, отчёты и журналы Blender — в каталогах заданий `data/jobs/`. Если локальный адрес работает, а публичный нет, проверьте `.runtime/tunnel.log` и доступность SSH `myserver`.
